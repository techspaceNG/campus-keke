# Campus Keke Production Deployment & Operations Guide

## 1. Hosting Architecture
- **Frontend**: [Vercel](https://vercel.com) (Serverless Next.js edge deployment).
- **Backend**: [Render](https://render.com), [Railway](https://railway.app), or [Fly.io](https://fly.io) (Long-running Node.js Docker / native runtime).
- **Database**: Managed PostgreSQL on [Neon](https://neon.tech), [Supabase](https://supabase.com), or AWS RDS.

---

## 2. Backend Deployment (Render / Railway / Docker)

### Environment Variables
Configure these in your backend hosting dashboard:

| Variable | Description | Example / Recommendation |
|---|---|---|
| `NODE_ENV` | Environment mode | `production` |
| `PORT` | Listening port | `5000` (or host injected) |
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://user:pass@ep-cool.us-east-1.neon.tech/campus_keke?sslmode=require` |
| `JWT_ACCESS_SECRET` | Secret key for access tokens | High-entropy string (64+ hex characters) |
| `JWT_REFRESH_SECRET` | Secret key for refresh tokens | High-entropy string (64+ hex characters) |
| `JWT_ACCESS_EXPIRES_IN` | Token lifespan | `1h` |
| `JWT_REFRESH_EXPIRES_IN`| Refresh lifespan | `7d` |
| `TICKET_QR_HMAC_SECRET` | Secret for signing ticket QR codes | High-entropy 64+ char secret |
| `CORS_ORIGIN` | Allowed Frontend URL | `https://campus-keke.vercel.app` |

### Production Build & Start Commands
```bash
# Install dependencies
npm ci

# Switch schema to PostgreSQL (if needed)
npx prisma generate --schema=prisma/schema.postgresql.prisma

# Execute pending database migrations
npx prisma migrate deploy --schema=prisma/schema.postgresql.prisma

# Build TypeScript
npm run build

# Start Production Server
npm start
```

### Dockerfile (Optional containerized deployment)
```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npx prisma generate --schema=prisma/schema.postgresql.prisma
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --only=production
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules/.prisma ./node_modules/.prisma
COPY --from=builder /app/prisma ./prisma
EXPOSE 5000
CMD ["npm", "start"]
```

## 4. Production Database Backups & Maintenance

### Automated Daily PostgreSQL Dumps
For PostgreSQL instances, schedule a daily cron job:
```bash
# Automated backup script
pg_dump -Fc --no-acl --no-owner -h <db_host> -U <db_user> campus_keke > /backups/keke_$(date +\%F).dump

# Retention: Remove backups older than 30 days
find /backups -type f -name "*.dump" -mtime +30 -exec rm {} +
```

### Health Checks & Monitoring
- **Health Check URL**: `GET https://<api-domain>/api/v1/health`
- Connect this URL to UptimeRobot, BetterUptime, or AWS Route53 health checks with a 60-second ping interval.
- Alerts will trigger if the database connection drops or API latency exceeds thresholds.

## 5. Security & Reliability Best Practices
1. **Never commit `.env` files** containing production secrets.
2. **Rotate JWT secrets** periodically without service interruption by supporting fallback verification keys.
3. **Database connection pooling**: For serverless or high-traffic scenarios, use PgBouncer or Neon connection pooling.
4. **Idempotency**: All ride activations require an `Idempotency-Key` header generated by the frontend to prevent accidental double-tap charges.
